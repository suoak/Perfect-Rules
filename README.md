# Suchen Rules

这是一套仅针对当前个人订阅设计的分流配置。

## 节点结构

配置会把订阅节点按名称自动划分为四个地区：

- 美国：`US001` 至 `US006`
- 日本：`JP001` 至 `JP003`
- 新加坡：`SG001`
- 韩国：`KOR01`

订阅更新后，配置可识别中英文地区名、国旗以及 `US/USA`、`JP/JPN`、`SG/SGP`、`KR/KOR` 等常见前缀，并自动进入对应地区组。

## 路由策略

规则按以下顺序匹配：

1. 公司内网、私有地址、`ruijie.com.cn`、`ruijie.com`、飞书和 Lark 全系域名直连。
2. OpenAI/ChatGPT/Codex、Anthropic/Claude/Claude Code、Google 全系及 Gemini、xAI/Grok 走 `🤖 国外 AI`。
3. GitHub、GitLab、Docker、npm、PyPI、JetBrains 等走 `💻 开发服务`。
4. 常见广告域名进入可随时关闭的 `🛡️ 广告拦截`。
5. 中国大陆域名和 IP 直连。
6. 其余流量全部走 `🚀 代理选择`。

AI 策略组不提供 `DIRECT`。所有 AI 域名先统一进入 `🤖 国外 AI`，再由 `🔒 AI 固定出口 US006` 使用同一个具体节点；默认锁定 `US006`，避免登录、API、上传和静态资源分别使用不同国家或出口 IP。选择会通过 `store-selected` 持久保存，网络切换和配置刷新不会自动改变。

AI 固定出口只列出具体订阅节点，不包含故障转移、地区测速或自动选择，杜绝测速和健康检查自动改变 AI 出口。`US006` 不可用时需要手动选择另一个具体节点，并在切换后重新登录相关 AI 账号。

四家 AI 厂商均配置了显式域名规则，包括网页、桌面/移动客户端、API、登录、静态资源、文件上传和长连接依赖；`GEOSITE,category-ai-!cn` 继续用作新域名的兜底。Google 全系统一使用 AI 固定出口，避免 Gemini 登录与 Google 账号服务使用不同 IP；`gstatic.com` 也不会再被公司内网拦截。

飞书和 Lark 同时使用进程、明确的品牌域名、会议主机及 GeoSite 直连规则，覆盖消息、文档、开放平台、文件、会议、RTC 和静态资源。规则不再直连整个字节海外 CDN 根域，避免 TikTok 等非飞书服务被误分流。相关域名使用系统 DNS 并绕过 Fake-IP，确保在公司、家庭及飞连环境中使用本地网络出口。

ChatGPT Voice 的 23 个官方 IPv4 地址已固定到 AI 出口，地址快照来自 OpenAI `chatgpt-voice.json`，生成时间为 2026-03-26。OpenAI 会动态更新该列表，后续维护配置时需要重新核对。访问 `https://api.ipify.org` 会强制经过 AI 固定出口，可用于确认当前公网 IP 是否仍然稳定。

运行 `node scripts/update-openai-voice.js` 可以从 OpenAI 官方地址重新获取 Voice IP，并同步更新三套配置及快照日期。脚本会校验响应内容，异常时不会用空列表覆盖现有规则。

## 广告拦截

Clash 使用 `GEOSITE,category-ads-all` 匹配常见广告域名，并通过 `🛡️ 广告拦截` 策略组控制。默认选择 `REJECT` 立即拒绝广告请求；遇到登录、支付、验证码或应用功能异常时，可临时切换为 `DIRECT` 排查，无需修改配置。

广告规则位于公司、飞书、AI 和开发服务之后，这些关键业务会优先匹配，不会被广告规则抢占。配置不叠加多个第三方广告列表，也不使用宽泛的域名关键词，以降低误拦截风险。域名级规则无法可靠屏蔽与正文共用域名、服务端插入或客户端内嵌的广告。

V2rayN 使用独立的 `block` 路由规则。发生误拦截时，在路由设置中禁用备注为“广告拦截（误拦截时可单独禁用）”的规则即可。

## 飞连兼容

- 节点测速使用 Cloudflare 的 `generate_204`，不依赖可能被内网拦截的 Google 域名。
- 测速每 600 秒按需执行，并严格校验 HTTP `204`，避免企业拦截页被误判为可用节点。
- DNS 仅监听 `127.0.0.1:1053`，不向局域网暴露解析服务。
- Mihomo 不接管私网、运营商级 NAT、回环和链路本地网段，这些流量由系统路由或飞连处理。
- TUN 关闭严格路由，减少 Windows 防火墙规则与飞连虚拟网卡、企业 DNS 冲突的概率。
- 内网、Apple 推送及系统连通性检测域名绕过 Fake-IP；内网域名不参与强制嗅探改写。
- TCP keep-alive 保持为 30 秒，兼顾 Codex、ChatGPT 和飞书的长连接。
- 浏览器不要指定 Google、Cloudflare 等自定义安全 DNS，建议使用系统 DNS，让 Mihomo 统一执行域名分流；Mihomo 上游仍使用加密 DNS。
- 当前关闭 IPv6，避免双栈网络下 AI 流量出现不同出口；在完整验证 IPv6 DNS 和 TUN 路径前不要单独开启。
- 建议先连接飞连，再启动 Clash；飞连优先使用极速模式。

## 使用方式

### 使用前准备

- 准备支持 Mihomo 覆写的 Clash 客户端，或使用支持自定义路由规则集的 V2rayN。
- 在客户端中单独添加自己的订阅，不要把订阅地址、令牌或生成后的完整节点信息提交到仓库。
- Clash 配置要求订阅中存在 `US006`；JS 覆写找不到它时会退回首个美国节点，静态 YAML 则需要手动把固定组中的节点名称改成订阅实际名称。
- 同一台设备只启用一个负责系统代理或 TUN 的客户端，避免 Clash、V2rayN、其他代理软件互相改写路由和 DNS。

### Clash Mi

1. 在客户端中添加并更新自己的订阅。
2. 把 [`Clash/Clash_mi.js`](./Clash/Clash_mi.js) 添加为当前订阅的 JS 覆写，并选择“内置-覆写”。
3. 重新生成或刷新配置，确认出现 `🚀 代理选择`、`🔒 AI 固定出口 US006`、`💻 开发服务` 和 `🛡️ 广告拦截`。
4. 保持 `🔒 AI 固定出口 US006` 选择 `US006`，`🛡️ 广告拦截` 默认选择 `REJECT`。
5. 需要接管未遵循系统代理的应用时启用 TUN；只使用浏览器时也可仅启用系统代理。

JS 脚本直接读取客户端已经获取的订阅节点，不保存订阅地址或凭据。订阅更新后，地区节点组会自动重新生成。

### Clash Verge / Mihomo

1. 在客户端中添加并更新自己的订阅。
2. 把 [`Clash/Clash_merge.yaml`](./Clash/Clash_merge.yaml) 添加为当前订阅的全局扩展覆写。
3. 重新加载配置，检查日志中没有找不到 `US006` 或 GeoSite 数据的错误。
4. 在代理组页面确认 AI 固定出口为 `US006`，普通国外流量使用 `🚀 代理选择`。
5. 广告误拦截时，仅把 `🛡️ 广告拦截` 切换到 `DIRECT`，不需要关闭整个代理。

地区组通过节点名称过滤，因此原订阅更新后通常无需重新生成本文件。如果订阅更改了节点命名，需要同步修改 `🔒 AI 固定出口 US006` 中的具体节点名称。

### V2rayN

1. 导入 [`V2rayN.json`](./V2rayN.json) 作为自定义路由规则集，并把它设为当前路由规则。
2. 在服务器列表中手动选择与 Clash 中 `US006` 对应的同一个节点。
3. 关闭自动切换、负载均衡和按域名选择不同服务器的功能，避免 AI 请求使用不同出口。
4. 发生广告误拦截时，禁用备注为“广告拦截（误拦截时可单独禁用）”的规则。
5. 修改规则后应重启核心或重新应用系统代理，直接修改运行时生成的临时配置不会持久保存。

V2rayN 路由文件只能决定 `direct`、`proxy` 或 `block`，不能在文件中绑定具体订阅节点。因此，固定 AI 出口依赖客户端当前手动选择的服务器。

### 公司与家庭网络切换

1. 需要飞连时先连接飞连，再启动或重新加载代理客户端。
2. 切换 Wi-Fi、有线网络或飞连状态后，重新连接 TUN，让系统路由按当前网卡重新生成。
3. 公司内网、锐捷和飞书应在连接日志中显示 `DIRECT`；AI 服务应显示 `🤖 国外 AI` 并最终使用 `US006`。
4. 在没有安装飞连的设备上，公开网站和 AI 分流仍可正常工作；只有依赖飞连授权或企业路由的内部资源无法访问。

### 首次验证

配置启用后按顺序检查：

1. 打开 `https://api.ipify.org`，记录 AI 固定出口的公网 IP；后续登录异常时先核对它是否变化。
2. 分别访问 ChatGPT、Claude、Gemini 和 Grok，确认连接日志都命中 `🤖 国外 AI`，没有落入自动选择或直连。
3. 打开 `https://www.gstatic.com/generate_204`，正常结果应为空白响应或 HTTP `204`，日志应命中 AI 固定出口。
4. 打开公司系统、`ruijie.com.cn`、`ruijie.com` 和飞书，确认日志显示 `DIRECT`。
5. 正常浏览常用网站；如出现登录、支付、验证码或页面持续等待，先把广告策略切到 `DIRECT` 复测。

### 常见问题

| 现象 | 排查方法 |
| --- | --- |
| AI 登录频繁失效 | 检查 `api.ipify.org` 的结果是否变化；不要在同一登录会话中切换 AI 节点或国家。 |
| 公司系统无法访问 | 确认飞连先于代理启动，并检查目标是否命中 `DIRECT`；只补充实际缺失的公司域名或 CIDR。 |
| `gstatic.com` 无法访问 | 确认命中 `🤖 国外 AI`，刷新客户端 DNS 缓存，并检查浏览器是否指定了独立安全 DNS。 |
| 开启广告拦截后页面变慢 | 将 `🛡️ 广告拦截` 切到 `DIRECT`；若恢复正常，再从连接日志定位误拦截域名。 |
| 广告仍然存在 | 域名规则无法处理同域广告、服务端插入广告和网页元素隐藏，这是预期限制。 |
| 切换公司和家庭网络后断网 | 重新连接 TUN；仍未恢复时先关闭 TUN，确认基础网络正常后再启动。 |

### 配置维护

- 每月运行一次 `node scripts/update-openai-voice.js`，更新 ChatGPT Voice 官方 IP。
- 订阅节点名称发生变化后，优先检查 `US006` 和四个地区组是否仍能正确匹配。
- 新增直连或 AI 域名时，应放在广告规则之前；不要把整个公共 CDN 根域直接放行。
- 广告规则出现误杀时优先增加精确例外，不叠加来源不明的脚本、重写规则或多个大型列表。
- 修改后至少执行 JS 语法、YAML/JSON 解析和规则顺序检查，再提交到仓库。

## 设计取舍

常见公共规则项目会拆分大量服务规则、远程下载规则集并每日自动更新，这适合通用配置，但也会引入第三方可用性、规则突变和重复匹配问题。本项目保持少量明确的业务分组，并优先使用客户端随 GeoSite 数据提供的类别，减少运行时外部依赖。

部分方案会在 DNS 层直接屏蔽广告，或者同时叠加多个广告和隐私列表。这样覆盖率更高，但误拦截时更难定位，也可能让应用等待 DNS 超时。本项目只使用一套 `category-ads-all`，并保留显式关闭入口。

普通代理配置常用 `url-test`、`fallback` 或负载均衡自动寻找可用节点；这适合网页浏览，但不适合要求账号出口一致的 AI 服务。因此普通国外流量继续自动选择，AI 流量独立固定到具体节点。后续更有价值的改进是增加自动化配置校验和可维护的精确白名单，而不是继续扩大默认直连范围或增加更多自动切换。
